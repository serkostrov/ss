# Привязка чатов Telegram и Max к рабочей группе

Messenger worker принимает сообщения из **каналов**, **групп/супергрупп** и **личных чатов** с ботом.

К одной рабочей группе — **один чат на платформу** (Telegram и/или Max). В UI переключение через вкладки платформ.

## Как появляется чат в списке

1. Запустите messenger worker (webhook зарегистрирован).
2. Добавьте бота АПСС:
   - в **канал** — администратором;
   - в **группу** — участником/админом;
   - в **ЛС** — пользователь пишет боту `/start` или любое сообщение.
3. В логах messenger: `Telegram webhook received` / `Max webhook received`.
4. Обновите форму привязки — чат появится в Select (с типом: Канал / Группа / Личные).

Если бот был добавлен **до** регистрации webhook — удалите и добавьте снова, либо напишите боту ещё раз.

## Telegram chat_id

- Канал / супергруппа: часто `-100…`
- Группа: отрицательный id
- ЛС: положительный user id

Перешлите сообщение боту `@RawDataBot` / `@getidsbot` или смотрите `chat.id` в webhook-логах.

## Max chat_id

В Max личный диалог и групповой чат адресуются по-разному:

- **ЛС** — в каталоге и при отправке используется `user_id` **отправителя** (`message.sender.user_id`), не `recipient.user_id` (часто это id бота)
- **Группа / канал** — используется `chat_id` чата; название берётся из Max API, не из имени добавившего пользователя

Если в списке привязки остались странные дубликаты («Группа: Имя Фамилия») или ошибка `Invalid chatId: 0` / `chat.not.found` при работающих входящих — **пересоберите messenger**, удалите привязку Max, снова напишите боту в ЛС и выберите чат «Личные». Исходящие подставят `author_external_id` из входящих, если привязка ещё указывает на id бота.

## После привязки

Сообщения из выбранного чата попадают в историю рабочей группы (админка и кабинет).
